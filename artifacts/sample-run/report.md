Current ways to add web search to an Ollama-based application include leveraging Ollama's native **Web Search API**, utilizing the **built-in web search feature in Claude Code**, integrating via an **MCP Server**, or employing **custom web scrapers**. The **Ollama Web Search API**, released on **September 24, 2025**, requires an API key and performs a `POST` request to `https://ollama.com/api/web_search` with a `query` and optional `max_results` (default **5**, maximum **10**) [1][2][3]. This API, accessible directly or through Python and JavaScript libraries, returns a JSON object containing an array of `results`, with each result providing `title`, `url`, and `content` [4]. When used as a tool within an agent, the model receives `WebSearchResult` objects containing the `content` [1][2]. For applications using **Claude Code**, as of **February 16, 2026**, web search is built into the Anthropic compatibility layer, allowing models to automatically handle searches and return results directly, often via subagents, without requiring additional configuration or API keys [5]. The **MCP Server** approach enables web search in clients like Cline, Codex, and Goose by running a Python MCP server that interfaces with Ollama's API, thus providing the same structured `title`, `url`, and `content` output to the integrated client [1][2][3]. Finally, **custom web scrapers**, built with tools such as Playwright or Selenium, can be integrated via tool-calling functionality to return highly customizable, structured JSON responses, extracting specific data like `h2` headings, paragraphs (`p1`), or code blocks directly from web pages [6][7].
