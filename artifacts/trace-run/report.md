Ollama offers several methods to integrate web search capabilities into applications. The primary approach is through the **Web Search API**, which is a REST API accessible via `POST https://ollama.com/api/web_search`. This API requires an API key from a free Ollama account and takes a `query` string and an optional `max_results` integer (defaulting to **5** and capping at **10**). The API returns a JSON object containing an array of `results`, where each result object includes the `title` (string), `url` (string), and `content` (string) of a relevant web page [1][2]. This API can be directly invoked or utilized through deeper tool integrations in Python and JavaScript libraries [1]. Another method involves **MCP (Multi-Context Processor) Server integration**, which uses a Python MCP server (`web-search-mcp.py`) to connect web search with clients like Cline, Codex, and Goose. When configured, these integrations leverage the same underlying Web Search API, thus providing the same structured JSON output of search results [1]. More recently, for specific Ollama cloud models such as `minimax-m2.5:cloud`, `glm-5:cloud`, and `kimi-k2.5:cloud`, web search is **built directly into the Anthropic compatibility layer**. This allows models to automatically perform web searches and integrate the results into their context or responses without requiring separate API keys or MCP server configurations, often using subagents to research topics in parallel [3]. In this integrated approach, Ollama handles the search and returns the content directly to the model, rather than a distinct JSON object to the user [3].
